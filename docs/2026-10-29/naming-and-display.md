# 节点命名/标签规范 + 侧栏 tag 展示与筛选（2026-10-29）

## 背景

节点名称（如 `TCE3.10.12.1-ARM准出验证-m7`）过长，侧栏 `truncate` 截断后丢失尾部的机器编号（`m7`），多个同前缀节点难以分辨。

## 解决方案：name 短标识 + tag 结构化属性

把「属性」与「标识」解耦：name 只做唯一标识，属性用 tag 表达。

```
name: <环境>-<机器编号>      ← 短标识，如 tce-m7
tags: [架构, 用途, 版本]      ← 结构化属性，用于筛选与识别
```

| 字段 | 规则 | 示例 |
|------|------|------|
| name | `环境-机器编号`，短、唯一、永不截断 | `tce-m7` |
| tags | 架构 / 用途 / 版本 | `[arm, 准出验证, 3.10.12.1]` |

tag 分类约定：

| tag 类别 | 取值 |
|---------|------|
| 架构 | `arm` / `x86` |
| 用途 | `准出验证` / `交付验证` / `研发` / `集测` |
| 版本 | `3.10.12.1` 等点分版本号 |

## 前端侧栏 tag 展示与筛选

`HostList.tsx` 改动：

- **tag chips 常驻展示**：每个节点的 tags 渲染为可点击的 chip，位于 name/副标题下方。
- **点击 tag 筛选**：点击某 tag（如 `arm`）过滤列表，仅显示「含该 tag 的节点及其祖先路径」；顶部显示「筛选: arm ✕」，再次点击或点 ✕ 取消。
- **name 精简后不再截断**：`环境-机器编号` 短名直接完整显示，机器编号一眼可辨。
- **保留智能断行 `splitNodeName`**：兼容历史五段式长名（如有未迁移节点），对新短名自动走 fallback 直显。
- 副标题（`→ IP · description`）增加 `title` 悬停提示。

## 顺带修复

- `tce-mr`（原 `TCE3.10.12.0-x86准出验证-mr`）的 `steps` 缩进错误：`steps:` 原本与 `entry` 平级，导致 YAML 同步时 steps 未被解析进 `entry`（API 返回 `steps: []`）。已修正为 `entry` 子字段。
